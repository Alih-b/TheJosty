# Evidence

The numbers the edition reports about its own reporting, and the record they come
from. Nothing here is a claim; everything here can be recomputed.

```bash
python3 source_report.py        # prints source-count.json from ledger.jsonl
```

## What is here

| file | what it is |
|---|---|
| `ledger.jsonl` | append-only, one JSON object per query, 13 rounds: the provider response for every backend attempted, the heal-ladder attempt that succeeded, the result count and the returned URLs |
| `round-2-calls.jsonl` | the call log for the edition's second reporting round: one object per invocation with status, result count, non-empty provider count and URLs |
| `round-14-probes.jsonl` | the October discovery round the edition's Press page describes: 45 probes with per-backend counts |
| `source-count.json` | the computed totals, regenerated by `source_report.py` |
| `source_report.py` | the counter |

## The corpus

- **126 queries across 13 rounds**
- **913 result entries**
- **839 distinct result URL strings**

Those are counts about the research backlog, not about the paper. The edition cites
**158 sources**; the 839 figure counts discovery URLs, including ones the edition
never used.

## Round two

- 40 recorded calls: 30 with results, 10 empty
- one earlier schema probe ran before logging existed and is not in this file, which
  is why the edition counts 41 invocations for that round

## The October round — and its limit

`round-14-probes.jsonl` is the round that produced this edition's newest material —
its fourth era of tooling. It records 45 probes and names the fallback provider on 36
of them, which is the record behind the Press page's account of a last-resort engine
answering with off-subject results.

Read its limits honestly: **it was produced by the working tree, and this evidence
directory is the first place it has shipped.** The corpus counts above come from the
ledger and do not include it.

## Two things worth knowing before you quote any of these numbers

1. **One backend carried it.** Across the ledger's run, five of the six configured
   backends returned `ok=true, error_kind=empty` on essentially every call, and one
   returned the results: 125 of 126 non-empty queries. A second backend answered 3.
   This is a single-engine result in one environment, not multi-engine corroboration.
2. **"Distinct" means distinct URL string.** Canonical aliases, relevance,
   accessibility and evidentiary quality are not deduplicated or verified by the
   counter. These are discovery counts, not counts of verified publications.

No comparison against any other search tool is made here, and none is claimed: no
other tool was run against these seeds.
